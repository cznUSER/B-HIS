## 切患 / 草稿 / 持久化策略

1. **切患确认（H02 §5.2）**  
   - 已有 `patientId` 再选另一患者：`selectOutpatientContext` → Frame `<dialog>`（标题「切换患者？」；确认/取消文案冻结）。  
   - 同患者换 `registerId`：标题「切换就诊？」并提示清空上一就诊未提交草稿。  
   - 首次从空选入：无需确认。  
   - 取消：上下文与草稿不变（`draftRevision` 不增）。

2. **确认后清空**  
   - `resetEpisode()` 清本机 episode：register/orders/diagnoses/charges/dispense/history/lastAction 等上一患者客户端草稿。  
   - **不**删除服务器已保存数据；新患者字段以本次选择/后续拉取为准（过敏全文不进持久化）。

3. **跨刷新仅 Id**  
   - `sessionStorage` 键 `bhis.outpatient.ids.v1`，值仅 `{ patientId, registerId? }`。  
   - 路由 query 同样仅允许这两 Id；**query 优先于 sessionStorage**，并回写纠正。  
   - `resolveOutpatientSelection`：未登录拒绝仅凭 Id 展示；登录后重新拉取患者/就诊。

4. **未选患者前置条件**  
   - `data-testid="outpatient-preconditions"` 可见提示：需先选患者与有效就诊。
