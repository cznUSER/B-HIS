## 1. 使用边界

本手册面向建档挂号员、门诊医生、收费员、药师和系统管理员。页面是否可进入、按钮是否可用，以服务端返回的有效权限、用户状态和科室范围为准；前端隐藏或禁用菜单不能替代服务端授权。

### 页面显示与滚动

1. 电脑端页面打开后，浏览器最右侧不得出现页面级纵向滚动条；页面根部、整页工作区和 `html/body` 的滚动不是正常操作方式。
2. 需要连续查看的内容只能在有明确尺寸边界的卡片/面板内容区内滚动，卡片标题、工具栏和分页区保持在卡片边界内。电子病历、订单明细、档案长文本、操作日志和打印预览属于可申请的卡片内滚动例外。
3. 患者档案、挂号、收费、发药、退药退费、库存、用户和审计等增长列表优先使用分页；翻页只更新结果区，不依赖拖动浏览器右侧滚动条。
4. 如果发现浏览器最右侧出现页面级滚动条，或滚动条出现在卡片外，记录页面路径和截图并交 H01/H05 处理；不要通过浏览器缩放掩盖问题。

首页工作台的“经营概况”卡片在窗口高度不足时，只在卡片内容区查看收费和客流指标；卡片标题、时间筛选和刷新按钮保持可见，不拖动浏览器最右侧滚动条。

## 2. 登录和账户

1. 打开网站登录页，输入账号和密码，提交登录。
2. 登录成功后进入 `/app` 首页；无权限的模块显示“无权限”，不应反复刷新绕过授权。
3. 账户被标记为必须改密时，系统会强制进入修改密码页，完成前不能进入其他页面。
4. 会话过期后系统回到登录页，并保留原目标地址；重新登录后按权限返回。
5. 忘记密码、账号停用或权限不足时联系系统管理员，不在浏览器中记录或发送密码。

## 3. 患者建档和查询

### 建档

前置条件：账号有患者建档权限，且已连接可用 API 和数据库。

1. 进入“档案管理 → 患者建档”。
2. 填写姓名、性别、出生日期、就诊卡/院内主索引等必填信息；身份证、电话和地址按机构要求填写。
3. 提交后记录页面返回的患者号/院内主键，并核对页面成功提示。
4. 如果证件号、卡号或院内主键重复，系统拒绝创建并提示冲突；不要通过修改已有患者资料来规避重复。

### 查询

1. 进入“档案管理 → 患者查询”。
2. 页面打开后默认加载患者档案列表，每批最多显示 100 条；列表底部可继续加载后续档案。需要缩小范围时再填写患者号、姓名、身份证号或院内档案号并查询。
3. 核对姓名、患者号、卡状态和最近记录；查询无结果时确认筛选条件后重试。
4. 无患者查询权限时由管理员调整授权，不能直接访问接口绕过页面。

## 4. 门诊业务主链

推荐顺序：

```text
建档 -> 挂号 -> 诊断/开单 -> 收费 -> 发药 -> 必要时退药 -> 退费
```

### 门诊共享基础（上下文 / 队列 / 状态链 / 提交反馈）

2026-10-31（P0-E 文档门禁）：门诊业务入口共用「患者上下文条 + 共享队列 + 状态链 + 提交反馈」。下列口径供一线操作与培训；不新增临床或支付规则。依据：[`H14 开工卡`](../../deliverables/h14/p0-e-integration-start-card-2026-10-31.md)、[`H05 集成复验`](../../deliverables/h05/p0-e-integration-2026-10-31.md)。本段不替代下文「医生工作站」独立队列说明。

**A · 患者上下文**

1. 挂号、诊断、开单、收费、发药、退药/退费等工作区共用同一当前患者与就诊号；顶栏应能看到姓名、患者号、性别·年龄、费别、过敏/高风险、就诊号、科室/医生、就诊日与流程状态。
2. 未选患者时，工作区会提示需先选患者与有效就诊；不要绕过前置条件直接开单或收费。
3. 已有患者后再换另一患者：系统弹出「切换患者？」；取消则保留原上下文与未提交草稿；确认后清空本机上一就诊草稿（不删除服务器已保存单据）。
4. 同患者换另一挂号：弹出「切换就诊？」；确认后同样清空上一就诊未提交草稿。
5. 刷新页面后仅恢复患者号/就诊号，再向服务端重拉详情；不要把浏览器里残留草稿当成已保存数据。

**B · 共享队列**

1. 从门诊总览「门诊队列」进入共享队列；按候诊 / 已接诊 / 诊疗中 / 待开单 / 待收费 / 待发药 / 暂停 / 退号分 Tab。
2. 点击队列行写入与上下文条相同的当前患者与就诊；进入诊断/开单等入口后无需再搜一遍患者。
3. 切换 Tab 或搜索不会丢掉当前已选患者（页面提示「当前患者保留中」）。
4. 空列表、加载失败、无权限是三种不同状态；无权限不等于「今天没有号」。按页面「重试」刷新；持续无权限交管理员核对科室范围。

**C · 状态链**

1. 上下文区的状态链用文字说明当前步骤（已完成 / 当前 / 待处理 / 阻塞 / 作废等）及原因；颜色只辅助，不以颜色单独表意。
2. 刷新后按当前就诊号回读挂号、诊断、开单、收费、发药只读聚合；某一域提示「无权限」时，不要当成「无数据」。
3. 退号或单据作废显示作废态；暂停显示阻塞态。看不清下一步时先点刷新，再对照队列 Tab。

**D · 提交反馈（高风险写操作）**

1. 挂号、诊断提交、开单提交、收费/支付、发药等写操作提交中按钮会锁定；成功横幅显示对应单号（挂号单号 / 诊断号 / 开单号 / 收费·结算号 / 发药单号），失败走统一错误弹框。
2. 网络超时或页面刷新后：先用原单号查询是否已成功，不要换新的幂等键再点一次。同键同请求在有效期内重放原结果；改金额或换键可能冲突或双单。
3. 业务拒绝（如号源满、冲突）按提示处理；服务端 5xx / 网络错误恢复后可再试，仍须先查单。

### 挂号

1. 首次进入挂号页且没有 `patientId` 时，点击“选择患者”；已有患者时点“更换患者”。弹窗打开后默认读取第一页 50 条，上一页/下一页均按每页 50 条加载。
2. 弹窗打开后可不输入关键词直接查看第一页；空关键词为全部未删除患者分页。输入关键词并查询时，系统按包含匹配姓名、电话、身份证号或姓名拼音首字母（助记码）。页面中的电话和身份证号为掩码值。
3. `ACTIVE`（在用）患者可选；`INACTIVE`（停用）患者仍显示但不可选。选择在用患者后，页面按该患者的 `patientId` 进入现有挂号流程；这一步只选择患者，不会创建挂号。更换患者会清空原挂号暂填项并回到当天现场号默认值。
4. 取消或关闭弹窗会保留原患者、当前路由和挂号暂填项。migration 022 与助记码回填完成后，患者选择查询 `POST /api/v1/patients/registration-search` 应返回 **200 分页**；关键词为空时加载全部未删除患者分页，**不是 400**。若查询服务暂不可用，按错误提示重试；**503 仅表示**助记码列缺失或仍有未回填行（可重试的 `SERVICE_UNAVAILABLE`），回填完成后不应再长期出现 503。503 不代表数据库迁移、回填或部署已经完成验收。
5. 在挂号主区域核对只读患者资料。当前页面固定使用当天、现场号，不提供就诊日期或接待方式选择，不能从当前页面新建预约。既有预约仍显示在患者挂号历史中；历史操作按该记录当前状态和账号权限执行。
6. 选择启用的科室和医生并核对挂号信息。当前号别固定为普通号；真实 API 模式可填写挂号费，默认 0。
7. “选择患者”“读取身份证”“读取医保卡”始终位于同一操作行。患者资料、科室/医生/时段选号、挂号确认和历史记录在同一挂号页显示。患者资料只读；选择患者只更新当前患者资料和关联历史。选号顺序为科室、医生、时段，余号为 0 的科室/医生/时段不可选。当前页面默认当天现场号；现有预约记录仍按预约信息显示在历史中，已退号的挂号不能继续开单或收费。保存后核对挂号单号、就诊日期和状态。
8. 报到仅适用于正常号或已用号，完成就诊仅适用于就诊中挂号，退号仅适用于正常号；这些操作仍受当前账号权限约束。重复提交应等待上一请求结果后再查询确认。

本次流程更新原因：挂号页增加患者选择弹窗，患者可在挂号流程内直接选择或更换，不再要求先进入独立患者查询页。证据来源：[`H03 挂号患者选择 API 契约`](../../deliverables/h03/register-patient-picker-api-contract-20261019.md)、`web/src/components/RegisterPatientPicker.vue`、`web/src/views/RegisterView.vue`、`web/src/api/patientApi.js`、`web/scripts/check-register-patient-picker.mjs`。2026-10-31（REG-DOC-01）按 [`H06 R5`](../../deliverables/h06/reg-patient-select-r5-review-2026-10-31.md)、[`H01 R3`](../../deliverables/h01/reg-r3-true-api-2026-10-31.md) 与 tip `0.3.11-draft` 澄清：回填完成后应为 200 分页（空 keyword 非 400；503 仅列缺失或回填未就绪）。隔离实例已有真 API/对账证据；其他库或生产仍须按实施部署手册完成 022/回填验收后方可宣称就绪。

### 医生工作站

进入“门诊业务 → 医生工作站”，左侧读取当天挂号队列。待诊包含正常号、已用号及诊中记录；已诊显示已完成就诊的记录，退号不进入队列。姓名、性别、年龄等来自患者档案，队列分类以挂号状态为准；档案“在用/停用”状态不替代挂号的接诊状态。队列沿用当前医生和科室范围筛选，以及服务端权限控制。

2026-10-21：新处方使用挂号单上的医生；继续编辑已有处方时保留原开方医生和科室。右侧纸面预览的医师姓名与该处方一致。登录账号编号不等于医生编号，管理员姓名不会自动成为处方医师。医生资料尚未读取、读取失败、缺失、停用或与科室不符时，保存会弹框说明原因并保留草稿；请先核对挂号医生和基础数据中的医生配置，再重试。

挂号保存后进入或重新打开医生工作站，核对左侧挂号单号与姓名。按挂号单显示记录，同一患者多次挂号会有多条记录。选择待诊记录进入接诊；已诊中的记录继续原接诊。若挂号页有当日记录但队列为空，核对就诊日期、医生科室范围和搜索条件，并保留两页截图交维护人员处理。

2026-10-21 修复记录：合并患者展示信息时保留挂号生命周期字段，避免在用患者的正常号或诊中号被误过滤。操作验收见 `deliverables/h01/doctor-queue-20261021/`。

右侧纸面预览标题旁的“实时”表示录入内容即时呈现。右上“全屏”按钮可将整个医生工作站铺满屏幕，包括患者队列、诊断与开单区、纸面预览；点击“退出全屏”或按 Esc 返回，已录入的内容保留。

处方单、处置单页签右侧显示当前单据类型：处方按已有类别显示，例如普通处方、毒麻处方、材料处方；处置单显示“检查检验处置”。新处方默认普通处方，已有处方保存时保留原类别。“保存处方/处置”“清空”“新方”按钮统一位于明细面板右下方。2026-10-21 四处界面调整验收证据见 `deliverables/h01/doctor-ui-four-adjustments-20261021/`。

### 诊断

1. 选择有效挂号进入“诊断”。
2. 输入结构化诊疗栏目，按页面提供的状态保存、提交或作废；已提交版本不能直接覆盖，可点击“修订此版本”，填写修订原因后生成新的修订草稿。
3. 保存成功后核对诊断状态和操作记录；本手册不定义临床诊断规则，临床口径由机构负责人确认。

### 开单

1. 选择有效挂号，进入“开单”。
2. 添加目录项目，核对项目类型、数量、单价和合计。
3. 可先保存草稿；确认无误后提交。
4. 已提交或已收费的单据不能直接改价；需要按系统提供的作废/退费流程处理。
5. 无有效挂号、空明细或金额不合法时，系统拒绝提交并显示错误原因。

### 收费

1. 进入“收费”，按患者号、挂号号、处方号或收费单号查询。
2. 核对患者、挂号、处方明细和应收金额。
3. 当前主路径为现金一次付清；输入实收金额后确认支付。
4. 收费成功后核对收费单号、支付状态和金额；刷新失败时先查询收费单，不要重复点击支付。
5. 收费只做库存可发性校验，不提前扣库存；真正扣库存发生在发药事务。
6. 网络超时、页面刷新或重复点击后，使用原收费单号查询支付状态；不要更换幂等键再次支付。相同请求在 24 小时内会重放原支付结果，金额或支付方式改变会返回冲突；超过 24 小时后进入正常业务状态校验，结果由当前收费单状态决定，不保证成功，收费员应先核对账单状态。

### 发药

1. 进入“发药”，检索已收费且尚未发完的处方，或打开“今日待发”。
2. 逐行核对患者、药品、规格、收费数量、已发数量、可发数量和库存。
3. 勾选明细并填写本次发药数量，确认发药。
4. 库存不足、未收费或已发完时，系统禁止发药；不要手工修改库存绕过校验。
5. 发药成功后核对发药单号和库存变化；列表刷新失败时先查询发药记录确认是否已提交。

### 退药和退费

1. 进入“退药/退费工作区”，选择“退药”或“退费”页签。
2. 已发药的收费单必须先在“退药”中选择可退明细，填写退药原因和数量并确认。
3. 退药成功后核对库存回加和可退数量，再进入“退费”。
4. 在“退费”中查询原收费单，核对退款金额、明细和支付记录后提交。
5. 退费失败时保留页面错误信息和收费单号，联系管理员或 H01 指定支持人员；不要重复提交造成并发冲突。
6. 含优惠收费单的部分退费策略以机构确认口径为准，本手册不自行扩大支持范围。

## 5. 基础数据维护

进入“系统设置 → 基础数据”，按权限维护：

- 科室：名称、编码、启停和排序。
- 医生：所属科室、编码和启停。
- 收费/药品目录：项目类型、编码、价格、启停和药品库存关联。
- 规则设置：统一维护科室、药品、处方、收费、支付、发药等业务编码的前缀、日期段、流水长度和重置周期；修改只影响后续生成的编码。
- 药品库存：查看库存；授权人员按 `inventory:adjust` 执行调整并填写原因。
- 基础字典：按字典类型维护有效代码和值。

基础数据变更会影响后续业务选择；删除、停用或调整库存前应确认没有未完成业务依赖，并保留审计记录。

## 6. 用户、角色、权限和审计

进入“系统设置 → 用户与权限”：

1. 用户账号：维护账号状态、角色绑定和必要的科室范围。
2. 角色与范围：核对角色允许的模块、权限和科室范围；显式禁用范围优先于旧的默认范围。
3. 权限目录：查看权限代码及所属模块，不直接把前端菜单显示当成授权。
4. 用户操作日志：按时间、用户、模块和结果查询审计记录。
5. 系统管理员保护：不要删除或停用系统最后一个可用管理员；遇到保护提示先走授权变更流程。

## 7. 常见错误和安全处理

2026-10-21：全站使用统一错误弹框提示接口失败和页面操作校验错误，覆盖登录、个人设置、患者档案、挂号、医生工作站、诊断、开单、收费、发药/退药、退费及系统管理。阅读原因后点击“确定”或按 Esc 关闭，再按提示更正或重试；关闭弹框不会自动重试、支付或提交。医生工作站全屏时也可见。并发产生的相同错误合并提示；关闭后再次操作仍失败时会重新提示。字段旁的校验说明可同时保留，便于找到需修改的位置。

| 现象 | 先做什么 | 不要做什么 |
|---|---|---|
| 无权限 | 记录用户、页面、时间和模块，交管理员核对权限/科室范围 | 不用别人的账号重试 |
| 找不到患者/挂号 | 清除筛选条件并查询患者号/挂号号 | 不凭姓名猜患者 |
| 重复提交 | 查询对应单号和状态，确认是否已成功 | 连续点击提交 |
| 切患后本机草稿不见了 | 确认切患会清空本机未提交草稿；查服务器已保存单据 | 把未保存草稿当已落库 |
| 队列显示无权限 | 核对账号科室范围后点重试 | 当成空队列或换别人账号 |
| 状态链与业务页不一致 | 点状态链刷新，核对是否同一就诊号 | 凭颜色猜测步骤 |
| 收费成功但页面报刷新失败 | 查询收费单和支付状态，保留原幂等键 | 更换幂等键再次支付 |
| 发药库存不足 | 核对可发数量和库存，联系药房管理员 | 手工改库存或拆单绕过规则 |
| 退费被要求先退药 | 回到退药页完成可退明细 | 直接调用退费接口 |
| 页面无法连接 | 检查 `/health` 和部署手册中的服务状态 | 修改浏览器或数据库配置碰运气 |
