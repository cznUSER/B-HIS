## 1. 文档用途和事实优先级

本手册说明网站的逻辑对象、物理表、接口边界、状态和数据约束。发生冲突时按以下顺序核对：

1. 目标 SQL Server 系统目录和已执行迁移记录，确认实际部署结构。
2. `migrations/sqlserver/core/*.up.sql`，确认工作区物理结构和约束。
3. `docs/contracts/数据模型.md`、`docs/contracts/库表约束.md`，确认逻辑模型和业务不变量。
4. `api/openapi.yaml`、`docs/contracts/接口契约.md`，确认 HTTP 请求/响应。
5. 本手册作为导读和维护索引，不替代上述源文件。

当前工作区的 `docs/database/系统数据库字段说明.md` 是 2026-10-15 的字段快照，明确说明它不是目标部署库的实时反向工程。契约版本存在 `0.3.10-draft` 与 `0.3.11-draft` 的历史差异，发布前必须以 `GET /health`、OpenAPI 和目标版本标签统一核对。

## 3. 核心对象和关系

| 逻辑对象 | 物理表 | 关键关系 |
|---|---|---|
| 患者 Patient | `dbo.patient` | 患者是一切门诊业务的主索引 |
| 科室 Department | `dbo.department` | 医生和挂号引用科室 |
| 医生 Doctor | `dbo.doctor` | 医生属于科室 |
| 就诊/挂号 RegisterBill | `dbo.register_bill` | 关联患者、科室、医生；API 中 encounterId 与 registerId 等价 |
| 目录 CatalogItem | `dbo.catalog_item` | `DRUG` 或 `TREAT`；药品与库存编码对齐 |
| 医嘱/处方 Order | `dbo.order_sheet`、`dbo.order_item` | 绑定患者和有效挂号 |
| 收费 Charge | `dbo.charge`、`dbo.charge_item` | 绑定有效挂号和处方/明细 |
| 支付 Payment | `dbo.payment` | 追加收费或退款记录，关联收费单 |
| 库存 Inventory | `dbo.inventory_item`、`dbo.inventory_ledger` | 方案 A 总量模型；流水只追加 |
| 发药 Dispense | `dbo.dispense`、`dbo.dispense_item` | 绑定处方、收费、挂号和患者 |
| 诊断 Diagnose | `dbo.diagnose` | 可选实体，绑定挂号；不定义临床规则 |
| 审计 Audit | `dbo.audit_log` | 业务事实和用户操作追溯 |
| 幂等记录 | `dbo.idempotency_record` | 按作用域和幂等键控制重复请求 |

主链为：

```text
Patient -> RegisterBill -> Order -> Charge/Payment -> Dispense -> InventoryLedger
                         \-> Diagnose
```

## 4. 关键状态和业务不变量

### 4.1 挂号

- 状态包括 `NORMAL`、`USED`、`DIAGNOSING`、`DIAGNOSED`、`PAUSED`、`BACK`。
- `BACK` 是终态；默认不能对已使用、就诊中、已完成或已挂起的挂号退号。
- 开单和收费必须绑定有效且未退号的挂号。

### 4.2 医嘱/收费

- 医嘱一期状态为 `SAVE`、`COMMIT`、`PROC`、`ABATE`。
- 只有 `SAVE` 可以修改明细；提交至少需要一行有效明细。
- 收费金额使用 `numeric(18,2)`；数量使用 `numeric(18,3)`，禁止使用浮点金额。
- 支付记录只追加，不物理删除；收费实收必须与应收金额满足接口契约。
- 收费创建、支付和退费的持久化幂等记录使用 `charge.create`、`charge.pay`、`charge.refund` 作用域；有效期为 24 小时，按服务端墙上时钟的 UTC 时间判断。重启后同一作用域、同一幂等键和同一请求内容在有效期内重放原结果；请求内容变化返回幂等冲突；过期键删除后进入正常业务状态校验，结果由当前收费单状态决定，不保证成功。
- 业务单据的 `created_at`、`paid_at` 等字段可以使用注入的业务时钟，但不能改变幂等记录的 UTC 有效期计算。

### 4.3 发药/退药/退费

- 只有已收费且收费单有效的 DRUG 明细可以发药。
- 发药扣减库存并追加 `DISPENSE` 流水；退药回加库存并追加 `RETURN` 流水，必须在同一业务事务内完成。
- 已发药的收费单退费前必须先完成对应退药，否则返回 `REFUND_REQUIRES_RETURN`。
- 全退作废原收费单；部分退保留未退部分的承接收费单，具体优惠分摊策略仍以用户确认口径为准。

### 4.4 库存和主数据

- `qty_on_hand` 不得为负；库存流水只追加。
- 期初、盘盈、盘亏统一使用 `biz_type=ADJUST`，不新造 `INIT` 类型。
- 科室、医生、目录和字典采用软删/启停与过滤唯一约束；审计、支付和库存流水不得物理删除。

### 4.5 患者列表分页

- `GET /patients` 使用 `offset`（从 0 开始）和可选 `limit` 分页；默认每页 100 条，服务端上限 100 条。
- 响应固定返回 `items`、`total` 和 `nextOffset`。`total` 是当前筛选条件下未删除患者数；旧适配器不提供计数时返回 `null`。没有下一页时 `nextOffset` 为 `null`。
- SQL Server 与 memory 实现都按 `created_at ASC, patient_id ASC` 排序；`patient_id` 是并列创建时间的稳定兜底键，避免连续翻页重复或遗漏。
- `total` 由同一筛选条件的计数查询得到；本次未新增表、字段或索引，软删条件仍为 `is_deleted = 0`。

### 4.6 挂号页今日工作数据

- 挂号页使用 `GET /registers?visitDate=YYYY-MM-DD` 读取当前账号科室权限范围内的当日挂号，沿用服务端最多 100 条的查询上限。
- `RegisterDto.patientName` 是从患者档案投影出的展示字段，与 `patientId` 一起返回；本次不新增数据库字段，也不复制患者姓名到 `dbo.register_bill`。
- 今日工作卡只显示患者姓名、挂号费用和挂号时间，记录溢出时在卡片内部滚动。

## 5. 权限、审计和敏感数据

网站权限以服务端返回的有效权限和科室范围为准，前端菜单只是可见性提示。典型权限包括 `patient:create`、`encounter:create`、`diagnose:write`、`order:submit`、`charge:pay`、`charge:refund`、`dispense:create`、`dispense:return` 和 `inventory:adjust`。

患者身份、证件、联系方式属于个人/医疗健康数据；支付金额、支付流水属于财务数据；密码、令牌和 DSN 属于账号凭据或配置秘密。文档、日志和测试证据不得写入密码、完整证件号、连接串口令或不必要的真实患者明细。

业务审计与运行日志分工如下：

- `audit_log`：记录谁在何时对哪一笔业务做了收费、退费、退药、退号等动作。
- 本地日志：记录请求、耗时、依赖错误、启动摘要和异常堆栈，不输出明文密码或完整身份证。
