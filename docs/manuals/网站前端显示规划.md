## 1. 目标

网站页面以业务操作为中心，减少每页重复的大型视觉页头，并让电脑端用户在当前工作台视口内完成主要判断和操作。所有页面均不得出现浏览器最右侧的页面级纵向滚动条；纵向溢出只允许在有明确高度边界的卡片/面板内容区内滚动，超出首屏的长列表优先分页。本项目不再投入移动端专门布局，页面设计、实现和验收优先针对电脑浏览器。

截图中的红框只作为本规划识别“大型页头”的视觉范围参考，不作为页面文字、按钮或数据的额外需求。

## 2. 统一页头规则

1. 移除 `BusinessPageHeader`、`master-page-header` 当前使用的大卡片、渐变背景、装饰圆环和大面积留白。
2. 保留一个紧凑的页面标题区域：面包屑、可访问的 `h1`、必要的短说明和当前页面必须的操作按钮。
3. 页面标题不能删除或降级为普通装饰文字；每个页面必须继续有唯一且可定位的 `h1`。
4. 标题区域使用普通布局和轻量分隔线，不再用完整圆角卡片包住整块区域。标题字号、间距和操作按钮按电脑端常用窗口宽度适配。
5. 页面自身不能因为页头样式产生额外纵向滚动；页面切换后焦点应回到页面标题或第一个主要操作。

## 3. 可视区与溢出规则

1. 所有页面的最外层文档/工作区不得出现页面级纵向滚动条。`html`、`body`、`#app`、shell 和页面根容器须按电脑端视口收缩；不能依赖浏览器窗口滚动来访问页面下方内容。
2. 页面布局使用可收缩的网格、`min-height: 0` 和受控的内容区。只有有明确高度边界的卡片/面板内部内容区可以设置纵向滚动；卡片标题、工具栏和分页区应保持在卡片边界内，不得把滚动条放到卡片外或浏览器最右侧。
3. 页面、shell 或导航容器不得以自身溢出制造右侧页面滚动条。确需滚动的导航应限定在导航自身区域内；任何例外都必须在页面验收记录中注明容器、理由和截图。
4. 表格允许横向滚动时，滚动必须限制在明确标注的表格容器内；禁止因单列过宽造成整个页面横向溢出。
5. 电子病历或临床编辑器、订单明细编辑区、患者档案长文本、操作日志明细和打印预览可在所在卡片内容区内滚动；这些例外不得放宽页面级滚动条禁令。

## 4. 分页规则

1. 患者档案、挂号/就诊记录、收费记录、发药记录、退药退费记录、目录、库存、用户、审计日志等可增长列表，必须使用服务端分页，不得为了填满页面一次性加载全部记录。
2. 默认每页建议 25 条；数据密度和业务场景允许时可提供 50 条或 100 条选项。默认值由 H03/H04 根据查询成本和页面高度确认。
3. 分页条至少显示总记录数（接口无法立即提供总数时要明确显示“总数加载中”）、当前页/总页数或可用的上一页/下一页状态，并提供首页、上一页、下一页、末页操作。
4. 翻页、改变每页数量或重新查询时，只更新结果区，不整页刷新；结果区应保留键盘焦点和加载/失败状态。
5. 查询条件变化后回到第一页。当前页没有记录时，自动回到最后一个有效页或显示空结果，不显示失真的页码。
6. API 契约需要明确 `offset` 或 `page`、每页上限、`total`、下一页状态和排序稳定性。排序字段必须固定，避免翻页时记录重复或遗漏。

## 5. 页面迁移顺序

### 第一阶段：共享基础

- H05 将两个大型页头收敛为同一套紧凑页头样式。
- H05 调整 shell 与业务页高度边界，增加统一分页组件和可访问状态。
- H03/H04 确认分页响应字段、总数策略、稳定排序和权限边界。

### 第二阶段：高频列表

- 患者查询先迁移，默认打开第一页档案并显示分页；选择患者后右侧详情保持在同一视口。
- 基础数据、用户、操作日志、库存和业务记录按同一分页组件迁移。
- 收费、发药、退药退费的查询结果必须保留业务状态、幂等提示和分页状态。

### 第三阶段：长内容例外与收口

- 临床编辑器、订单明细和档案长文本改为面板内滚动，并标注例外原因。
- H06 使用真实路由或等价只读夹具复核电脑视口；首轮验收尺寸为 1280×720、1440×900 和本次需求截图对应的 1880×954。移动端专门布局与移动视口验收不属于本项目本轮目标。
- H18 更新操作手册的查询、翻页和例外滚动步骤；H13 更新部署手册中的前端构建、回滚和缓存清理影响（有影响时）。

## 7. 验收标准

1. 所有被验收页面在目标电脑视口内均不得显示浏览器最右侧页面级纵向滚动条；检查 `document.documentElement.scrollHeight <= document.documentElement.clientHeight` 且 `window.scrollY === 0`。另逐个验证卡片内部滚动容器可滚动，且其溢出不扩大页面根高度。
2. 标准页面不再出现大型卡片式页头；仍存在唯一可访问的 `h1`，标题和主要操作可见且不互相遮挡。
3. 列表首屏只请求当前页数据；翻页请求带有明确页码/偏移量，结果顺序稳定，连续翻页没有重复或遗漏。
4. 页面无非预期横向溢出；表格横向滚动仅发生在标注的表格容器内。浏览器最右侧不能出现页面级纵向滚动条，纵向滚动条只可出现在卡片/面板内部内容区。
5. 查询、翻页、空结果、加载中、失败和权限不足均有可读反馈；键盘可以进入筛选、翻页和列表选择。
6. H01 收口前必须记录代码提交短 SHA、GitLab 分支和推送结果；有代码/API/界面变化时，同一任务必须同步更新受影响手册。

## 8. 文档影响评估

- 网站操作手册：实施分页和页头改造后必须更新；本规划阶段只登记目标，不改变当前操作事实。
- 网站数据结构文档：若新增总数查询、索引或排序字段，必须由 H03 在接口/数据库变更同一任务中更新。
- 实施部署手册：只有构建参数、静态资源缓存、反向代理或回滚步骤受影响时才更新；无影响时在任务回报中记录“文档影响评估=无”。
