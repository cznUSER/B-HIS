## 1. 角色定义（Phase 1）

| 角色代码 | 名称 | 职责（H02） | HERP 线索 |
|----------|------|-------------|-----------|
| REGISTRAR | 建档挂号员 | 建档、发卡（可选）、挂号、退号 | UI/Card、UI/register |
| DOCTOR | 门诊医生 | 接诊、诊断、开处方/医嘱、提交 | UI/Doctor |
| CASHIER | 收费员 | 划价确认、收款、退费 | UI/Charge |
| PHARMACIST | 药房人员 | 发药、退药（含原因） | UI/Drugs |
| SYSTEM | 系统（管理员+审计） | 状态机/校验配置、用户角色、审计查询；种子数据 | Classes/Data + SQL |

> v0.1 的 ADMIN / AUDITOR 合并为 **SYSTEM** 能力集；实现上仍可拆 `ADMIN` 与 `AUDITOR` 子角色（权限取并集），对外文档以 H02 五类为准。

同一用户可多角色；权限取并集。

### 2.1 敏感操作附加规则

| 操作 | 附加 |
|------|------|
| 退号 | 校验六态规则；成功须写 back_operator_id / back_operated_at；审计必记 |
| 退费 | 须 reason（建议）；仅 CanBack；Abate+新单同事务；**已发药明细须先退药再退费**（B-08，否则 `REFUND_REQUIRES_RETURN`）；审计必记金额/数量 |
| 退药 | **原因必填**；数量 ≤ 已发未退；审计必记 |
| 取消已有进行中业务的挂号 | 按状态机；有已收费未退完须先走退费链路（业务提示） |
| 毒麻精抗处方权 | **本版关闭**（C-09 / A34）；feature flag 默认 **off**；开启前不做处方权校验、不因毒麻精抗拒单 |
| 库存调整 | 须 `inventory:adjust` 或 `admin:*`；remark 建议必填；调后 ≥0；审计 **`inventory.adjust`** |
| 主数据启停 | 停用后业务下拉不可新选；历史单据仍可展示名称/快照 |

## 3. 鉴权模型（骨架）

```
User 1──* UserRole *──1 Role 1──* RolePermission *──1 Permission
```

权限码建议：`patient:create`、`encounter:create`、`encounter:cancel`、`order:submit`、`order:recipe-check`、`charge:pay`、`charge:refund`、`dispense:create`、`dispense:return`、`inventory:read`、**`inventory:adjust`**、`audit:read`、`admin:*`。

主数据维护（#24）：默认需 **SYSTEM** 或 `admin:*`（亦可细拆 `department:*` / `doctor:*` / `catalog:*` / `dict:*` / `user:*`，Phase1 可用 `admin:*` 覆盖）。

**H09 强制补列**：写库存调整须 `inventory:adjust` **或** `admin:*`。

### 3.1 登录相关约定（v0.3.2）

| API | 谁可调 | 说明 |
|-----|--------|------|
| `POST /auth/login` | **匿名** | 校验用户名/密码；成功发 JWT |
| `GET /auth/me` | **已登录** | 任意有效 Bearer；返回当前用户与 `roles[]` |
| `POST /auth/logout` | **已登录** | 使 token 失效 + 审计 LOGOUT |

### 3.2 种子用户（开发/演示）

| 项 | 约定 |
|----|------|
| 建用户 | 仅 **SYSTEM**（或实现期管理 API）可建用户与赋角色 |
| Phase1 预置 | 管理员用户名 **`system`**（角色 `SYSTEM`，拍板#15）；各角色演示账号可预置（如 `registrar` / `doctor` / `cashier` / `pharmacist`） |
| 密码 | 演示口令均为 **`1`**（管理员与员工默认，拍板#15/#16）；实现期 **bcrypt/argon2 哈希入库**；脚本/Git **禁止**写可利用的明文生产口令；见 `migrations/sqlserver/core/009_seed_auth_users.sql` 草案 |
| 停用 | `status=DISABLED` → 登录与后续请求 `403 ACCOUNT_DISABLED` |

## 4. 审计字段约定

### 4.1 业务表公共列

| 列 | 类型 | 说明 |
|----|------|------|
| created_at | timestamptz | |
| created_by | varchar(64) | 工号/用户 id |
| updated_at | timestamptz | |
| updated_by | varchar(64) | |
| is_deleted | boolean | 若启用软删 |

### 4.2 关键业务留痕列（对齐 H02）

| 场景 | 字段 | 说明 |
|------|------|------|
| 退号 | encounter.back_operator_id, back_operated_at | 必填（成功时） |
| 退费 | payment + charge.successor / abated_from；audit remark=原因 | 原单/新单号均记 |
| 退药 | dispense.return_reason；操作员 | 原因必填 |
| 收费/发药 | created_by / dispensed_at | |

### 4.3 审计日志表 `audit_log`（只追加）

| 列 | 说明 |
|----|------|
| audit_id | UUID PK |
| occurred_at | 事件时间 |
| actor_id / actor_roles | 谁 + 角色快照 |
| action | 如 `encounter.cancel` / `charge.refund` / `dispense.return` / **`inventory.adjust`** / `department.*` / `doctor.*` / `catalog.*` / `user.*` / `dict.*` |
| resource_type / resource_id / resource_no | 单据 |
| outcome | SUCCESS / FAIL |
| error_code | 失败时（含 REGISTER_BACK_NOT_ALLOWED 等） |
| before_state / after_state | jsonb 摘要（退费须含旧/新 square_no、金额） |
| request_id / idempotency_key / client_ip | 可空 |
| remark | 退费/退药原因 |

**必须审计**：建档、挂号、退号、开单提交、收费、退费、发药、退药、**库存调整**、主数据维护（科室/医生/目录/用户/码表）、权限变更。

### 4.4 主数据 / 库存维护审计 action（v0.3.10）

| action | 时机 |
|--------|------|
| `department.create` / `department.update` / `department.deactivate` | 科室维护 |
| `doctor.create` / `doctor.update` / `doctor.deactivate` | 医生维护 |
| `catalog.create` / `catalog.update` / `catalog.deactivate` | 目录维护 |
| **`inventory.adjust`** | 总量调整成功（#24f / H09；ledger ADJUST 同行） |
| `dict.create` / `dict.update` | 可维护码表 |
| `user.create` / `user.update` / `user.deactivate` / `user.reset_password` | 轻量用户；**勿记明文口令** |

**登录相关审计**（写入 `audit_log` 或安全专用日志，可与运行 log 关联 `request_id`）：

| action | outcome | 备注 |
|--------|---------|------|
| `LOGIN_SUCCESS` | SUCCESS | actor=登录用户；勿记密码 |
| `LOGIN_FAILURE` | FAIL | actor 可空或尝试的 username（注意隐私）；`error_code=INVALID_CREDENTIALS` 等；勿记密码 |
| `LOGOUT` | SUCCESS | actor=当前用户；可记 jti 摘要 |

非法状态跳转失败亦写 FAIL（假设，供 H06）。

## 5. 与 H06 衔接

1. 无角色收费 → 403  
2. 药房人员退费 → 403  
3. 退号/退费/退药成功后 audit 可查操作员与原因  
4. 退号拒绝（就诊中）→ FAIL 审计 + 状态不变  
5. 错误密码登录 → `LOGIN_FAILURE` 可查且不泄露密码；正确登录 → `LOGIN_SUCCESS`  
6. 过期 token 调业务 API → 401 TOKEN_EXPIRED
