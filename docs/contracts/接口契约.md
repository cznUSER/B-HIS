## 1. 通用约定

### 1.1 协议

| 项 | 约定 |
|----|------|
| Base URL | `/api/v1` |
| Content-Type | `application/json; charset=utf-8` |
| 时间 | ISO-8601，带时区（存 UTC，展示 Asia/Shanghai） |
| 金额 | 语义 `decimal(18,2)`；禁 float |
| 认证 | `Authorization: Bearer <token>` |
| 幂等 | 写操作支持 `Idempotency-Key: <uuid>` |
| 追踪 | 可选 `X-Request-Id` |

### 1.2 错误包络

```json
{
  "success": false,
  "data": null,
  "error": {
    "code": "ILLEGAL_STATE_TRANSITION",
    "message": "当前状态不允许该操作",
    "details": { }
  },
  "requestId": "..."
}
```

### 1.3 错误码

| HTTP | code | 含义 |
|------|------|------|
| 400 | VALIDATION_ERROR | 字段校验失败（含生日非法、Amount≤0） |
| 401 | UNAUTHORIZED | 未认证（缺 Bearer / 未登录） |
| 401 | INVALID_CREDENTIALS | 用户名或密码错误（**勿区分**哪个字段，防枚举） |
| 401 | TOKEN_EXPIRED | accessToken 已过期 |
| 401 | TOKEN_INVALID | accessToken 无效/被篡改/已注销 |
| 403 | FORBIDDEN | 无权限 |
| 403 | ACCOUNT_DISABLED | 账号已停用 |
| 429 | AUTH_RATE_LIMITED | 登录失败过频（可选建议；实现可按 IP/用户名限流） |
| 404 | NOT_FOUND | 资源不存在（含 Square 查无） |
| 409 | DUPLICATE_PATIENT | 证件/卡号重复建档（拒绝） |
| 409 | DUPLICATE_CARD_NO | 卡号重复 |
| 409 | IDEMPOTENCY_KEY_CONFLICT | 同键不同体 |
| 409 | ILLEGAL_STATE_TRANSITION | 状态机拒绝 |
| 409 | REGISTER_BACK_NOT_ALLOWED | 退号拒绝（已 BACK 或已用/就诊中等且参数禁止） |
| 409 | ENCOUNTER_REQUIRED | 需要有效挂号（A27 默认；未挂号策略待确认） |
| 409 | INSUFFICIENT_STOCK | 库存不足（方案 A / 收费禁止策略） |
| 409 | CHARGE_AMOUNT_MISMATCH | 金额不一致 |
| 409 | REFUND_EXCEEDS_REFUNDABLE | 退费超额 |
| 409 | ITEM_NOT_CAN_BACK | 明细 CanBack=false |
| 409 | REFUND_REQUIRES_RETURN | 已发药须先退药（**待确认**，H02 B-07；契约保留） |
| 409 | NOT_CHARGED | 未收费不可发药 |
| 409 | ALREADY_DISPENSED / ALREADY_ABATED | 重复发药 / 结算已作废 |
| 422 | BUSINESS_RULE_VIOLATION | 其它业务规则 |
| 501 | NOT_IMPLEMENTED | 方案 B 下 inventory 可 501 |

## 3.0 Auth（登录鉴权 · v0.3.2）

> 供 **H04**（Go API）与 **H05**（Vue3 登录页）先行落地。门诊业务 UI 仍可按原拍板暂缓。

### 3.0.1 Token 默认推荐（Phase1）

| 项 | 约定 |
|----|------|
| **默认方案** | **JWT access token（HS256）** |
| 声明建议 | `sub`=userId；`username`；`roles`（数组）；`iat` / `exp`；可选 `jti` |
| TTL | **默认 8h**，可配置（如 `Auth.AccessTokenTTL`） |
| 传递 | `Authorization: Bearer <accessToken>` |
| refresh | **延后**（Phase1 不实现 refresh token） |
| 备选 | 服务端 session + opaque token（须会话表）；若改用须同步改 OpenAPI 说明 |
| 密钥 | 仅存服务端配置；**禁止**写入仓库；Host 可读本地配置 |

### 3.0.2 `POST /auth/login`（匿名）

**Request**

```json
{
  "username": "admin",
  "password": "••••••••"
}
```

**Response `200`**

```json
{
  "accessToken": "<jwt>",
  "tokenType": "Bearer",
  "expiresIn": 28800,
  "user": {
    "id": "…",
    "username": "admin",
    "displayName": "系统管理员",
    "roles": ["SYSTEM"]
  }
}
```

| 失败 | HTTP / code |
|------|-------------|
| 用户名或密码错误 | `401 INVALID_CREDENTIALS`（文案统一，勿泄露「用户不存在」） |
| 账号停用 | `403 ACCOUNT_DISABLED` |
| 过频失败 | `429 AUTH_RATE_LIMITED`（可选） |

### 3.0.3 `POST /auth/logout`（需 Bearer）

- 成功：`204` 无体，或 `200 { "success": true }`
- **服务端使 token 失效**：
  - **推荐**：若 JWT 带 `jti`，写入短时黑名单/撤销表（TTL ≥ 剩余有效期）；或维护服务端会话表并删会话
  - **最低可接受（文档化）**：无黑名单时，客户端丢弃 token；契约仍要求调用本接口以便审计 `LOGOUT`；实现须在 README 标明「无服务端撤销」风险
- 缺/坏 token → `401 TOKEN_INVALID` / `UNAUTHORIZED`

### 3.0.4 `GET /auth/me`（需 Bearer）

**Response `200`** — 与 login 中 `user` 同形（可加 `roles[]` 权限码扩展字段，Phase1 可选）：

```json
{
  "id": "…",
  "username": "admin",
  "displayName": "系统管理员",
  "roles": ["SYSTEM"]
}
```

| 失败 | code |
|------|------|
| 未带 token | `401 UNAUTHORIZED` |
| 过期 | `401 TOKEN_EXPIRED` |
| 无效/已注销 | `401 TOKEN_INVALID` |
| 账号已停用 | `403 ACCOUNT_DISABLED` |

### 3.0.5 安全约定

| 项 | 约定 |
|----|------|
| HTTPS | 现场可选；本机开发可用 HTTP（localhost） |
| 密码 | **不落运行日志**、不进 audit 明文；仅存哈希（实现期选定算法，如 bcrypt/argon2） |
| 失败响应 | **不返回**「用户名错 / 密码错」细分；`details` 不回显密码 |
| 审计 | 建议写 `LOGIN_SUCCESS` / `LOGIN_FAILURE` / `LOGOUT`（见《权限与审计》） |
| CORS | Vue 开发机调本机 API 时，API 须对开发源放行（见《架构方案草案》） |

## 3. 资源与主要 DTO

### 3.1 Patients

**`POST /patients`**

```json
{
  "name": "张三",
  "sex": "M",
  "birthday": "1990-01-15",
  "idType": "ID_CARD",
  "idNumber": "110101199001151234",
  "cardNo": "C202610120001",
  "phone": "13800000000",
  "fareIdentity": "SELF"
}
```

校验：姓名必填；birthday>1900-01-01 且≤今天；证件/卡号冲突 → `409 DUPLICATE_PATIENT` / `DUPLICATE_CARD_NO`（**拒绝不合并**，A20）。

`PatientDto`：`patientId, hospPkNo, patientNo, cardNo, name, sex, birthday, idNumber, phone, fareIdentity, cardStatus, status, createdAt`

发卡时 `cardStatus` 可由 NOT_SENT→NORMAL（发卡金延后）。

### 3.2 Encounters

**`POST /encounters`** → `status=NORMAL`；字段含 `deptCode, doctorId, clinicSort, visitDate, registerFee, registerCharged`。

**`POST /encounters/{id}/check-in`** → `DIAGNOSING`（自 NORMAL 或 USED）。

**`POST /encounters/{id}/complete`** → `DIAGNOSED`（自 DIAGNOSING）。

**`POST /encounters/{id}/cancel`（退号）**

| 当前状态 | 默认行为 |
|----------|----------|
| BACK | 拒绝 `REGISTER_BACK_NOT_ALLOWED` |
| USED / DIAGNOSING / DIAGNOSED / PAUSED | 拒绝（参数允许退已用号时可放开） |
| NORMAL | → BACK；写 `backOperatorId` / `backOperatedAt` |

`EncounterDto`：`encounterId, encounterNo, patientId, deptCode, doctorId, clinicSort, visitDate, status, registerFee, registerCharged, registeredAt, backOperatorId, backOperatedAt`

### 3.3 Orders

**`POST /orders`**：默认要求有效 Encounter（≠BACK）；否则 `ENCOUNTER_REQUIRED`（A27）。

状态：创建为 NEW/SAVE；`PATCH` 仅 SAVE；`submit` → COMMIT。

可选 `POST …/recipe-check` → RECIPE_CHECK。

`OrderItemDto`：`orderItemId, lineNo, itemNo, itemType, itemName, amount, price, totalFee, doctorId, procDepartmentId, unit`

`OrderDto`：`orderId, orderNo, encounterId, status, recipeSort, items[], submittedAt`

### 3.4 Charges（Square）& Payments

**载入待收**：自已 COMMIT 处方生成/获取 Charge（`POST /charges` 或 submit 后 charge-preview）。

**`POST /charges/{chargeId}/pay`**

```json
{ "paymentNo": "可选", "payType": "CASH", "amount": 31.00 }
```

Phase1：`payType` 以 `CASH` 为主，可选一种电子；微信/支付宝全链路延后。  
成功：Square 保持/确认为 `NORMAL`；Payment `direction=CHARGE, status=SUCCEEDED`。  
卡状态非 NORMAL 时部分路径拒绝（C-05）。

**`POST /charges/{chargeId}/refund`**（对齐 AbateSquareBill）

```json
{
  "reason": "患者要求",
  "payType": "CASH",
  "items": [
    { "chargeItemId": "…", "refundQty": 1 }
  ]
}
```

规则：

1. 仅 `canBack=true` 明细可入选；否则 `ITEM_NOT_CAN_BACK`  
2. `0 < refundQty ≤ 可退数量`  
3. **同事务**：原 Square → `ABATE`；生成 **新** Square（`NORMAL`）承接未退部分（全退时新单金额可为 0 或不生成——实现须在响应写明，对齐 AC-09/10）  
4. 写 Payment `direction=REFUND`  
5. 主路径建议已退药；若仍已发未退，可返回 `REFUND_REQUIRES_RETURN`（**待确认**）  
6. 已 ABATE → `ALREADY_ABATED` / NOT_FOUND

响应建议：`RefundResultDto { abatedSquare, newSquare?, refundPayment }`

### 3.5 Dispense

**`POST /orders/{orderId}/dispense`**

前置：存在覆盖该处方的 `NORMAL` Square（charged）；Order∈{COMMIT, RECIPE_CHECK}；明细非空。  
方案 A：事务内 CheckStorages + 扣减；不足 → `INSUFFICIENT_STOCK`。  
成功：Order→`PROC`。

**`POST /dispenses/{dispenseId}/return`**

```json
{
  "reason": "必填",
  "items": [ { "dispenseItemId": "…", "qty": 1 } ]
}
```

成功：Order→`RECIPE_UNCHECK`；方案 A 回滚库存。

### 3.6 Diagnose（可选）

`POST /encounters/{id}/diagnoses` → SAVE；`…/commit`；`…/abate`。Upload 不提供。

### 3.7 Inventory（方案 A）

`GET /inventory/items`；方案 A 启用查询；StatusOnly 实验降级时可 501。

## 4. 状态前置条件速查

| API | 前置 | 成功后 |
|-----|------|--------|
| cancel encounter | NORMAL（默认）；非 BACK | BACK |
| submit order | SAVE | COMMIT |
| recipe-check | COMMIT | RECIPE_CHECK |
| pay | Charge 待收/可收 | Square NORMAL + Payment |
| dispense | COMMIT/RECIPE_CHECK + charged | PROC |
| return dispense | PROC（已发） | RECIPE_UNCHECK |
| refund | Square NORMAL | 旧 ABATE + 新 NORMAL（若有未退） |

非法跳转 → `409 ILLEGAL_STATE_TRANSITION`。
