## 1. 通用约定

### 1.1 协议

| 项 | 约定 |
|----|------|
| Base URL | `/api/v1` |
| Content-Type | `application/json; charset=utf-8` |
| 时间 | ISO-8601，带时区（存 UTC，展示 Asia/Shanghai） |
| 金额 | 语义 `decimal(18,2)`；禁 float |
| 认证 | `Authorization: Bearer <token>` |
| 幂等 | 写操作支持 `Idempotency-Key: <uuid>` |
| 追踪 | 可选 `X-Request-Id` |

### 1.2 错误包络

```json
{
  "success": false,
  "data": null,
  "error": {
    "code": "ILLEGAL_STATE_TRANSITION",
    "message": "当前状态不允许该操作",
    "details": { }
  },
  "requestId": "..."
}
```

## 3.0 Auth（登录鉴权 · v0.3.2）

> 供 **H04**（Go API）与 **H05**（Vue3 登录页）先行落地。门诊业务 UI 仍可按原拍板暂缓。

### 3.0.1 Token 默认推荐（Phase1）

| 项 | 约定 |
|----|------|
| **默认方案** | **JWT access token（HS256）** |
| 声明建议 | `sub`=userId；`username`；`roles`（数组）；`iat` / `exp`；可选 `jti` |
| TTL | **默认 8h**，可配置（如 `Auth.AccessTokenTTL`） |
| 传递 | `Authorization: Bearer <accessToken>` |
| refresh | **延后**（Phase1 不实现 refresh token） |
| 备选 | 服务端 session + opaque token（须会话表）；若改用须同步改 OpenAPI 说明 |
| 密钥 | 仅存服务端配置；**禁止**写入仓库；Host 可读本地配置 |

### 3.0.2 `POST /auth/login`（匿名）

**Request**

```json
{
  "username": "admin",
  "password": "••••••••"
}
```

**Response `200`**

```json
{
  "accessToken": "<jwt>",
  "tokenType": "Bearer",
  "expiresIn": 28800,
  "user": {
    "id": "…",
    "username": "admin",
    "displayName": "系统管理员",
    "roles": ["SYSTEM"]
  }
}
```

| 失败 | HTTP / code |
|------|-------------|
| 用户名或密码错误 | `401 INVALID_CREDENTIALS`（文案统一，勿泄露「用户不存在」） |
| 账号停用 | `403 ACCOUNT_DISABLED` |
| 过频失败 | `429 AUTH_RATE_LIMITED`（可选） |

### 3.0.3 `POST /auth/logout`（需 Bearer）

- 成功：`204` 无体，或 `200 { "success": true }`
- **服务端使 token 失效**：
  - **推荐**：若 JWT 带 `jti`，写入短时黑名单/撤销表（TTL ≥ 剩余有效期）；或维护服务端会话表并删会话
  - **最低可接受（文档化）**：无黑名单时，客户端丢弃 token；契约仍要求调用本接口以便审计 `LOGOUT`；实现须在 README 标明「无服务端撤销」风险
- 缺/坏 token → `401 TOKEN_INVALID` / `UNAUTHORIZED`

### 3.0.4 `GET /auth/me`（需 Bearer）

**Response `200`** — 与 login 中 `user` 同形（可加 `roles[]` 权限码扩展字段，Phase1 可选）：

```json
{
  "id": "…",
  "username": "admin",
  "displayName": "系统管理员",
  "roles": ["SYSTEM"]
}
```

| 失败 | code |
|------|------|
| 未带 token | `401 UNAUTHORIZED` |
| 过期 | `401 TOKEN_EXPIRED` |
| 无效/已注销 | `401 TOKEN_INVALID` |
| 账号已停用 | `403 ACCOUNT_DISABLED` |

### 3.0.5 安全约定

| 项 | 约定 |
|----|------|
| HTTPS | 现场可选；本机开发可用 HTTP（localhost） |
| 密码 | **不落运行日志**、不进 audit 明文；仅存哈希（实现期选定算法，如 bcrypt/argon2） |
| 失败响应 | **不返回**「用户名错 / 密码错」细分；`details` 不回显密码 |
| 审计 | 建议写 `LOGIN_SUCCESS` / `LOGIN_FAILURE` / `LOGOUT`（见《权限与审计》） |
| CORS | Vue 开发机调本机 API 时，API 须对开发源放行（见《架构方案草案》） |

## 3. 资源与主要 DTO

### 3.1 Patients

**`POST /patients`**

```json
{
  "name": "张三",
  "sex": "M",
  "birthday": "1990-01-15",
  "idType": "ID_CARD",
  "idNumber": "110101199001151234",
  "cardNo": "C202610120001",
  "phone": "13800000000",
  "address": "上海市浦东新区示例路 1 号",
  "fareIdentity": "SELF"
}
```

**必填（对齐 H02《建档字段清单-给H05.md》）**：`name`、`sex`、`birthday`、`fareIdentity`。  
**选填**：`idType`、`idNumber`、`cardNo`、`phone`、`address`（可空）。

校验：
| 规则 | 行为 |
|------|------|
| birthday | `>1900-01-01` 且 `≤` 服务器当天；非法 → `400 VALIDATION_ERROR`（DB CHECK 仅保证 `>1900-01-01`） |
| idNumber 非空 | 与其它未删患者冲突 → `409 DUPLICATE_ID_NUMBER`（或 `DUPLICATE_PATIENT`）；**拒绝创建，不合并**（拍板#20 / A20） |
| cardNo 非空 | 冲突 → `409 DUPLICATE_CARD_NO`；拒绝不合并 |
| address | 选填可空；search 可按 `address` 模糊（可选） |

`PatientDto`：`patientId, hospPkNo, patientNo, cardNo, name, sex, birthday, idNumber, phone, address, fareIdentity, cardStatus, status, createdAt`  
（`patientId` 契约侧 uuid 格式字符串；实现库存 `varchar(64)`，见迁移 `002_patient`。）

发卡时 `cardStatus` 可由 NOT_SENT→NORMAL（发卡金延后）。

**`GET /patients`**：查询参数 `cardNo` / `idNumber` / `name` / `hospPkNo` / `address`（可选模糊）。  
**`GET /patients/{id}`**：详情。

### 3.2 Registers（挂号；Encounter ≡ RegisterBill）

> 对齐 H02《挂号字段清单-给H05.md》、拍板#19、AC-03/AC-04。  
> **主路径 `/registers`**；旧 `/encounters*` 为 deprecated alias。  
> 订单/收费字段名可继续用 `encounterId`（语义 **≡ `registerId`**）。

**`POST /registers`** → `status=NORMAL`

| 字段 | 必填 | 说明 |
|------|------|------|
| patientId | Y | 须已建档；不存在 → `PATIENT_NOT_FOUND` |
| departmentId | Y | 科室主数据；不存在 → `DEPARTMENT_NOT_FOUND`；种子 `dept-1`/`dept-2` |
| doctorId | Y | 医生主数据；不存在 → `DOCTOR_NOT_FOUND`；种子 `doc-1`/`doc-2` |
| visitDate | Y | 就诊日 |
| registerSort | N | 号别可选占位（如 `sort-normal`） |
| registerFee | N | 默认 `0`；一期可不做正式结算 |

**`GET /registers`**：查询参数 `patientId` / `registerNo` / `visitDate`（可选）。  
**`GET /registers/{registerId}`**：详情。

**`POST /registers/{id}/check-in`** → `DIAGNOSING`（可延后实现）。  
**`POST /registers/{id}/complete`** → `DIAGNOSED`（可延后实现）。

**`POST /registers/{id}/cancel`（退号）**

| 当前状态 | 默认行为 | 错误码 |
|----------|----------|--------|
| NORMAL | → BACK；写 `backOperatorId` / `backOperatedAt` | —（AC-04） |
| USED / DIAGNOSING / DIAGNOSED / PAUSED | **拒绝**；状态不变 | `REGISTER_NOT_CANCELLABLE`（AC-03） |
| BACK | **拒绝**（不可再退） | `REGISTER_BACK_NOT_ALLOWED` |

一期不允许退已用号（无开关 UI）。

`RegisterDto`：`registerId, registerNo, patientId, departmentId, doctorId, registerSort, visitDate, status, registerFee, registerCharged, registeredAt, backOperatorId, backOperatedAt`  
（`registerCharged` 默认 `false`；迁移见 `003_register`。）

### 3.3 Orders（P1-H03-ORDER / 拍板#21）

> 对齐 H02《开单字段清单-给H05.md》；迁移 `004_order`（+ seed DRUG-A/DRUG-B/TREAT-1）。  
> 主字段名 **`registerId`**；`encounterId` 为同义别名（≡registerId）。无 Go handler（归 H04）。

#### 状态机（一期四态）

```
SAVE（暂存） ──commit──► COMMIT（可收费） ──发药──► PROC
   │                        │
   └──────── abate ─────────┘──► ABATE（终态；仅 charged=false）
```

| 操作 | 前置 | 结果 | 错误码 |
|------|------|------|--------|
| `POST /orders` | 有效挂号 status≠BACK | status=SAVE | `ENCOUNTER_REQUIRED`（无挂号/已退号 BACK） |
| `PATCH /orders/{id}` | status=SAVE | 改头/全量替换 items | `ORDER_NOT_EDITABLE` |
| `POST …/commit` | SAVE；≥1 行；amount>0 | → COMMIT；totalFee=Σ；submittedAt | `ORDER_NOT_COMMITTABLE` / `ORDER_EMPTY_ITEMS` / `ORDER_INVALID_AMOUNT` / `ENCOUNTER_REQUIRED` |
| `POST …/submit` | 同 commit | **deprecated alias** | 同 commit |
| `POST …/abate` | SAVE/COMMIT 且 charged=false | → ABATE | `ORDER_CHARGED_NOT_ABATABLE` |
| `POST …/recipe-check` | — | **一期跳过**（501 或透传） | — |

#### 与挂号衔接（退号不可开）

- **强制**有效 `registerId`：挂号存在且 `status ≠ BACK`（拍板#21a / O-P1）。  
- 无挂号、挂号不存在、或已退号（BACK）→ **拒绝开单/提交**，返回 `409 ENCOUNTER_REQUIRED`。  
- 一张挂号 **允许多张** 处方（#21d）；`order_sheet.register_id` 无唯一约束。  
- 开单医生默认=挂号医生，**允许改**（#21b）；科室默认挂号科室。  
- `patientId` 由挂号带出落库；请求若传须与挂号一致。  
- `diagnoseName` **不强制**（#21c）。

#### 业务规则

| ID | 规则 |
|----|------|
| O-P1 | 无有效 registerId（含 BACK）不可开单/提交 → `ENCOUNTER_REQUIRED` |
| O-P2 | commit 至少 1 行；每行 amount>0 |
| O-P3 | commit 后 totalFee=Σ明细；可供收费 |
| O-P4 | 已收费（charged=true）不可改数量/不可 abate → `ORDER_CHARGED_NOT_ABATABLE` |
| O-P5 | 毒麻精抗本版关（A34 / #21g）；feature flag 默认 off |
| O-P6 | 开单库存 **仅提示不拦**（#21f）；收费侧再拦 |
| — | 处方审核一期跳过；目录=药品 DRUG + 可选治疗 TREAT；不做长期医嘱/检验检查 |

**毒麻精抗处方权（C-09 / A34 / #21g）**：本版校验 **关闭**；配置预留 feature flag（如 `Feature.ControlledRxAuthorityCheck`，**默认 off**）。

#### DTO

### 3.4 Charges（Square）& Payments

> 对齐拍板 **#13 / #22** + H08《交接说明-给H03H04.md》《状态与流程.md》《金额核对点.md》。  
> OpenAPI version **0.3.8-draft**；迁移 `005_charge`。验收以 OpenAPI 为准。

**资源字段要点**

| 资源 | 关键字段 | 备注 |
|------|----------|------|
| Charge（Square） | `squareNo`, **`registerId`（必填；`encounterId`≡别名）**, `orderId`, `totalFee`/`squareFee`/`favourableFee`, `status` NORMAL\|ABATE, `successorChargeId`, `abatedFromId`, `paidAt` | #22a / C-07：无有效挂号不可创建/支付 → `ENCOUNTER_REQUIRED` |
| ChargeItem | `qty`, `unitPrice`, `canBack`, `refundedQty`, 关联 `orderItemId` | qty>0（C-02） |
| Payment | `paymentNo`, `chargeId`, `direction` CHARGE\|REFUND, `payType`, `amount`, `status`, `paidAt` | Phase1 演示 `CASH`；电子枚举预留；成功 **`SUCCEEDED`** |

**API 最小集（#22i）**

| 能力 | API | 前置 | 成功后 |
|------|-----|------|--------|
| 费用预览 | `GET /orders/{orderId}/charge-preview` | Order=COMMIT；有效挂号 | 待收口径明细+应收（可未落库） |
| 载入/生成待收 | `POST /charges`（body.`orderId`） | 同上；收费侧库存（#22g） | Charge 待收（`paidAt=null`） |
| 支付 | `POST /charges/{chargeId}/pay` | 现金一次付清；`amount=squareFee` | NORMAL + `paidAt` + Payment CHARGE |
| 退费 | `POST /charges/{chargeId}/refund` | NORMAL；CanBack；**已发则已退药** | ABATE + 可选新 NORMAL + Payment REFUND |
| 详情 | `GET /charges/{chargeId}` | — | ChargeDto |
| 列表 | `GET /charges?patientId` / `registerId`\|`encounterId` / `visitDate` 或 `from`+`to` | — | items[] |

**默认不拆（#22d / A21）**：一处方一张 Charge；实现默认 1:1；不建强制 `uk_charge_order`。

**载入待收**：自已 COMMIT 处方生成 Charge。创建时 **必须** 写入有效 `registerId`（经 Order→Register，status≠BACK）；否则 `ENCOUNTER_REQUIRED`。库存不足 → `INSUFFICIENT_STOCK`（收费侧拦；开单只提示）。

**`POST /charges/{chargeId}/pay`**

前置：**须绑定有效挂号**（`register_id` 必填且 status≠BACK）；否则 `ENCOUNTER_REQUIRED`（#22a）。禁止无挂号仅凭卡号直接收费。

```json
{ "paymentNo": "可选", "payType": "CASH", "amount": 31.00 }
```

- Phase1 支付（#22b / C-08 / A09）：演示路径 **`CASH` 一次付清**；电子字段（`OTHER_E`/`WECHAT`/`ALIPAY`）**可落库预留，不联调**。  
- **实收=应收（#22f）**：`amount` **必须等于** `squareFee`；否则 `CHARGE_AMOUNT_MISMATCH` / `INVALID_AMOUNT`（不允许多收找零）。  
- 库存不足 → `INSUFFICIENT_STOCK`（#22g）。  
- 成功：Square=`NORMAL`；写 `paidAt`；Payment `direction=CHARGE, status=SUCCEEDED`。  
- 金额核对（优惠 \(F=0\) 时 **硬断言**）：H08《金额核对点》**K-01～K-05**（#22c）。

**`POST /charges/{chargeId}/refund`**（对齐 AbateSquareBill / H08 §1.4 / #22e/#22h）

```json
{
  "reason": "患者要求",
  "payType": "CASH",
  "favourableAlloc": "PROPORTIONAL",
  "items": [
    { "chargeItemId": "…", "refundQty": 1 }
  ]
}
```

- `favourableAlloc`：可选；**默认可配 `PROPORTIONAL`（#22c / H08 草稿，非正式拍板，不硬断言）**。  
- 策略枚举（契约预留）：`PROPORTIONAL` | `DISCOUNT_ON_REMAIN` | `DISCOUNT_FIRST`。公式见 H08《金额核对点》**§4**。  
- **Phase1 验收**：\(F=0\) 路径可硬断言；\(F>0\) 期望值待用户经 H01 确认。

**前置（#22h / B-08 / A10 · 已确认强制）**：

- Square 须为 `NORMAL`；已 ABATE → `ALREADY_ABATED`  
- **已发药**明细：必须先退药；否则 **`409 REFUND_REQUIRES_RETURN`**  
- 未发药明细：可直接按 CanBack 退费

规则：

1. 仅 `canBack=true`；否则 `ITEM_NOT_CAN_BACK`  
2. `0 < refundQty ≤ 可退数量`；超额 → `REFUND_EXCEEDS_REFUNDABLE`  
3. **同事务**：原 Square → `ABATE`（记 `successorChargeId`）；若有未退数量生成 **新** Square（`NORMAL`，`abatedFromId`→原单）  
4. **全退（#22e）**：**不生成**金额为 0 的新 Square；响应 **`newSquare=null`**  
5. 写 Payment `direction=REFUND`，成功态 **`SUCCEEDED`**  
6. \(F=0\) 时 \(Pay^{ref}=∑(q'×p)\)、\(R^{new}=∑(q_rem×p)\) 可硬断言；金额非法 → `INVALID_AMOUNT`

响应：`RefundResultDto { abatedCharge, newSquare?, refundPayment }`（全退 `newSquare=null`）。

**错误码（稳定，H08 §1.3 / #22）**：`ENCOUNTER_REQUIRED`、`INSUFFICIENT_STOCK`、`INVALID_AMOUNT`、`ITEM_NOT_CAN_BACK`、`REFUND_REQUIRES_RETURN`、`REFUND_EXCEEDS_REFUNDABLE`、`ALREADY_ABATED`、`NOT_CHARGED`、`CHARGE_AMOUNT_MISMATCH`。

**已收费作废（#22j）**：订单 `…/abate` 在 `charged=true` 时仍拒 → `ORDER_CHARGED_NOT_ABATABLE`（须走退费链）；charge-preview 随本片收口。

### 3.5 Dispense（P1-H03-DISPENSE / 拍板#23 / H02 发药清单 / H09 口径）

> 迁移：`006_inventory` + `007_dispense`。仅 **DRUG**；TREAT 不进发药/库存。毒麻本版不拦（#23g）。

**数量公式（与 H02/H09 一致）**

| 概念 | key | 口径 |
|------|-----|------|
| 已收费数量 | `chargedQty` | 开单/收费明细数量 |
| 已发净量 | `dispensedQty`（净） | 累计已发 − 累计已退 |
| 可发数量 | `availableQty` | `chargedQty − dispensedQty` |
| 本次发药 | `dispenseQty` | `0 < qty ≤ availableQty`；默认可发；可改小 |
| 行态 | `lineDispenseStatus` | `NONE` / `PARTIAL` / `FULL`（净发相对 charged） |
| 库存提示 | `stockHint` / `stockQty` | 发前展示；确认硬拦 |

**`POST /dispenses`**（主路径；`POST /orders/{orderId}/dispense` 为 deprecated 别名）

```json
{
  "orderId": "…",
  "chargeId": "…",
  "items": [
    { "chargeItemId": "…", "orderItemId": "…", "dispenseQty": 1 }
  ]
}
```

前置：Charge `status=NORMAL` 且 `paidAt≠null`；否则 **`NOT_CHARGED`**。空明细 → `EMPTY_DISPENSE_ITEMS`；超量 → `DISPENSE_EXCEEDS_AVAILABLE`；已满发 → `ALREADY_DISPENSED`。  
**同事务**（方案 A / H09）：CheckStorages → 扣 `qty_on_hand` → ledger(`DISPENSE`,负) → 建发药单；不足 → `INSUFFICIENT_STOCK`（不改库存）。  
**收费只拦不预扣**；真实扣减只在发药。成功：有净发 → Order→`PROC`；允许部分发，剩余可再发。

**`GET /dispenses`** / **`GET /dispenses/{dispenseId}`**：已发查询（患者/挂号/收费/处方/日）。

**`POST /dispenses/{dispenseId}/return`**

```json
{
  "reason": "必填",
  "items": [ { "dispenseItemId": "…", "returnQty": 1 } ]
}
```

`reason` 空 → `RETURN_REASON_REQUIRED`；超量 → `RETURN_EXCEEDS_DISPENSE`；未发 → `NOT_DISPENSED`。  
**同事务**：回加库存 → ledger(`RETURN`,正) → 更新 `qty_returned`。  
与退费（#13/#23f）：净发>0 的明细退费 → **`REFUND_REQUIRES_RETURN`**；退药成功后该明细可退费；未发明细可直接退费。  
Order 一期 DB 仍四态（不扩 `RECIPE_UNCHECK`）；**退费前置以行净发数量判定**。

### 3.7 Inventory（方案 A · 006 + 维护调整 · 008）

| API | 说明 |
