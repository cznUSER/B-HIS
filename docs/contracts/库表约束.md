## 1. 总则

| 原则 | 约定 |
|------|------|
| 主键 | 代理键 **`varchar(64)`**（可存 uuid 格式字符串；对齐 identity/`app_user.user_id`）；不用业务号作 PK |
| 业务键 | UNIQUE；全局单号唯一 |
| 外键 | Phase 1 **建议启用物理 FK**（同库单体） |
| 删除 | 主数据软删；payment / ledger / audit **禁止物理删** |
| 级联 | **禁止**业务主数据 ON DELETE CASCADE |

| 舍入 | 行金额 HalfUp 到分（A08 待拍板） |
| 物理表名 | **不照搬 HERP**；逻辑字段可注明对照 |

## 4. 状态检查（CHECK / 应用状态机）

| 表.列 | 允许值 | 备注 |
|-------|--------|------|
| register_bill.status | NORMAL, USED, BACK, DIAGNOSING, DIAGNOSED, PAUSED | 对齐 TRegisterStatus；默认 NORMAL |
| department.status / doctor.status | ACTIVE, INACTIVE | |
| order_sheet.status | SAVE, COMMIT, PROC, ABATE | 一期四态（004 CHECK）；RECIPE_CHECK 等延后 |
| catalog_item.item_type | DRUG, TREAT | |
| catalog_item.status | ACTIVE, INACTIVE | |
| order_item.item_type | DRUG, TREAT | |
| order_item.amount | `> 0` | CHECK |
| order_item.total_fee | `>= 0` | CHECK |
| charge.status | NORMAL, ABATE | TSquareStatus |
| patient.card_status | NOT_SENT, NORMAL, LOST, CANCELLED | TInsideCardStatus |
| patient.birthday | `> '1900-01-01'`（CHECK） | `≤今天` 由应用校验 |
| patient.address | nvarchar(256) NULL | 选填可空；可索引模糊查 |
| diagnose.status | NEW, SAVE, COMMIT, ABATE | 可选 |
| payment.status | PENDING, SUCCEEDED, FAILED | |
| charge_item.amount | `> 0` | 收费提交 |
| charge_item.can_back | boolean NOT NULL | 默认 true/按业务 |

非法跳转由应用状态机拒绝；DB CHECK 保证枚举域。

**退号**：应用层强制 —— 仅 `NORMAL→BACK`（AC-04）；`USED/DIAGNOSING/DIAGNOSED/PAUSED` → `REGISTER_NOT_CANCELLABLE`（AC-03）；已 BACK → `REGISTER_BACK_NOT_ALLOWED`。

**开单（004 / 拍板#21）**：应用层强制 —— 有效 `register_id` 且 status≠BACK，否则 `ENCOUNTER_REQUIRED`；仅 SAVE 可 PATCH；commit 须 ≥1 行且 amount>0；abate 仅 charged=false 的 SAVE/COMMIT；一张挂号多处方（无 UK on register_id）。

**退费同事务（强制）**：

```
BEGIN;
  -- 0) 前置（B-08 已确认强制）：已发药明细须已退药；否则应用层返回 REFUND_REQUIRES_RETURN，不进事务
  -- 1) 校验 Square NORMAL、明细 can_back、refundQty；收费侧须绑定有效 Encounter（C-07）
  -- 2) UPDATE charge SET status='ABATE' WHERE id=:old AND status='NORMAL';
  -- 3) INSERT 新 charge (NORMAL, abated_from_id=old) 承接未退部分（全退可跳过或金额0）；
  --    UPDATE 原单 successor_square_id；金额按 favourableAlloc（默认 PROPORTIONAL，H08 草稿待确认）
  --    ※ F=0 可硬断言 K-10～K-15；F>0 策略可配置，期望值待用户确认（A35）
  -- 4) 更新明细 refunded_qty；写 payment REFUND status=SUCCEEDED
  -- 5) 写 audit_log
COMMIT;
```

条件更新行数为 0 → 视为并发/已作废失败（AC-13/14）。

## 5. 金额与数量

| 字段类别 | 类型 | CHECK |
|----------|------|-------|
| price, total_fee, square_fee, favourable_fee, payment.amount | numeric(18,2) | `>= 0` |
| amount / qty（业务数量） | numeric(18,3) | 明细 `> 0`；流水可负 |
| qty_on_hand | numeric(18,3) | `>= 0` |

合计：`charge.total_fee = SUM(charge_item.total_fee)`（应用层强制）。

**部分退 / 优惠分摊（A35）**：策略枚举可配置 — `PROPORTIONAL`（H08 推荐草稿）| `DISCOUNT_ON_REMAIN` | `DISCOUNT_FIRST`；公式见 H08《金额核对点》§4。**非用户已拍板**。Phase1：\(F=0\) 硬断言 K-01～K-15；\(F>0\) 期望值待用户经 H01 确认。金额非法 → 应用层 `INVALID_AMOUNT`。
