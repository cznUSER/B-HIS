## 8. 运行日志落盘（拍板#6 · 必须）

### 8.1 与业务 audit 的分工

| 通道 | 存哪 | 用途 | 典型内容 |
|------|------|------|----------|
| **audit 表** | SQL Server `audit_log` | 业务事实、合规追溯 | 谁在何时对哪张单据做了收费/退费/退号/退药等 |
| **log 文件** | 本地磁盘 | 运行可观测、排障 | 请求进出、耗时、依赖错误、panic/栈、启动配置摘要 |

二者互补：业务成功/失败关键动作**既**写 audit（结构化）**又**打 log（可含 request_id 关联）。

### 8.2 级别

`debug` | `info` | `warn` | `error`  
默认生产/现场：`info`；排障可将 Host 切换为 `debug`。

### 8.3 必含字段（每条结构化日志）

| 字段 | 说明 |
|------|------|
| `timestamp` | ISO-8601，建议 UTC 存、展示转 Asia/Shanghai |
| `level` | debug/info/warn/error |
| `request_id` / `trace_id` | 来自 `X-Request-Id` 或服务端生成；全链路透传 |
| `actor_id` | 操作者；匿名/系统写 `system` 或空并注明 |
| `action` | 如 `charge.pay`、`encounter.cancel`、`http.request` |
| `resource_type` | Patient/Encounter/Order/Charge/Dispense/… |
| `resource_id` | 资源主键或业务单号 |
| `outcome` | SUCCESS / FAIL / 或 HTTP 状态语义 |
| `error_code` | 失败时业务错误码（如 `INSUFFICIENT_STOCK`） |
| `duration_ms` | 耗时（请求或用例级） |

推荐 JSON Lines（每行一条 JSON），便于检索。

### 8.4 路径与滚动

| 项 | 约定 |
|----|------|
| 默认目录 | `{安装目录}/logs/` 或配置 `Logging.Dir`（实现仓相对 `E:\B-HIS\logs`） |
| 文件名 | `h-api-YYYYMMDD.log`（或按大小滚动的 `h-api.log` + 备份名） |
| 滚动 | 按日或按大小（如 64MB）；保留备份数/天数见配置 |
| 权限 | 仅本机服务账户/管理员可写读；Host「打开日志目录」 |
| 禁止 | 日志中输出明文口令、完整身份证（可脱敏）、连接串密码 |
| Git | **`logs/` 不进仓库**（见 §2.0.3） |

### 8.5 Host 侧

- 菜单/按钮：打开日志目录、打开当日日志  
- API 未启动时 Host 自身日志（`h-host-*.log`）同样落盘
