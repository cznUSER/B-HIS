# Cursor CLI 协作说明

更新时间：2026-10-18（北京时间）

Cursor CLI 在 B-HIS 中作为 H01 管理的临时代码协作者使用，优先承接 H04/H05 的小型、边界明确的实现切片。它不替代 H01-H18 长期岗位，也不会因 CLI 可用就自动获得项目写入权限。

## 派工门槛

每次任务必须先给出任务编号、目标、允许修改文件、禁止触碰文件、依赖契约、验收命令、文档影响评估和回报格式。H01 负责确认任务是真实待办，并检查与当前未提交改动、共享文件所有权和交接冻结的冲突。

## 执行约束

- 先读取 `AGENTS.md`、任务指定契约和相关源码。
- 业务改动先写失败测试，确认失败后再写最小实现。
- 不自行决定临床、支付、权限、数据库或上线规则。
- 不修改任务白名单以外的文件，不提交、推送、部署或写生产库。
- 找不到可复现缺口时回报阻塞，不制造行为。

## 收口证据

Cursor 必须回报实际修改文件、失败测试、修复说明、最终测试结果、文档影响和未覆盖风险。H01 通过独立 diff 检查和新鲜测试结果验收，再决定 GitLab 提交与推送。纯分析任务标记为 `GitLab同步=不适用`；产生项目文件变更时按 H01 规程同步 GitLab。
